用 Agent Skill
跑完整場工作坊。 Run the Whole Workshop
with Agent Skill.

這頁教你怎麼用 AI coding agent（Claude Code 或 Codex）自動跑完 工作坊當日腳本手動教的同一套流程——從燒錄韌體到兩段即時 demo 對照。Agent 幫你處理操作細節，但每一步在做什麼、為什麼，你都會清楚看到——目的是讓你體驗完整的部署流程，不是把流程藏起來。 This page covers using an AI coding agent (Claude Code or Codex) to automatically run the same flow the Workshop Day Scripts page teaches manually — from flashing firmware to the two side-by-side live demos. The agent handles the operational details, but you'll still clearly see what's happening and why at every stage — the point is to experience the full deployment pipeline, not hide it behind automation.

燒錄韌體Flash the Firmware只有需要才有only if flashing

人機協作：你負責兩次實體切換（切到 EDL mode、切回 Normal mode），agent 負責搜尋韌體路徑、驗證裝置 ID、執行 qdl.exe、燒完用 adb 驗證真的開機成功。任何一步失敗都不會自動重試，會停下來給你看 log。qdl.exe 燒錄本身約 10 分鐘以上，加上兩次人工切換的時間。Human-machine collaborative: you handle the two physical switches (to EDL mode, back to Normal mode); the agent finds the firmware path, verifies the device ID, runs qdl.exe, then verifies over adb that it actually booted. 環境確認Environment CheckStep 0–2

依序裝 adb、裝 Docker 載入 iQ-Foundry 工具鏈、登入 Qualcomm AI Hub。這是唯一需要連網的一步；量化好的模型已經在套件裡，之後全程可以離線。Installs adb, installs Docker and loads the iQ-Foundry toolchain, logs into Qualcomm AI Hub. This is the only step that needs network access; the quantized model already ships in the package, so everything after this can run offline.

關卡：要不要繼續 INT8？Gate: Continue into INT8?

裝置端測試On-Device TestStep 7

用 adb 把測試圖丟到 Q911，實際跑一次 INT8 推論，存下偵測結果圖——mAP 是數字，這步是眼見為憑。Pushes test images to the Q911 via adb, runs INT8 inference for real, saves the detection results — mAP is a number, this is the eyeball proof.

INT8 即時 demoINT8 Live DemoStep 8

同一台板子、同一組影片，把模型從 FP32 換成 INT8 再跑一次 9 路偵測，直接比較畫面跟 FPS，是整場的收尾對照。Same board, same videos, model swapped from FP32 to INT8, running 9-channel detection again — a direct before/after comparison, picture and FPS, to close things out.

整體約 15–25 分鐘（不含兩段 demo 想看多久，以及燒錄與兩次人工切換的時間）；每一步任何一個失敗，腳本會立刻整個停下來，agent 對照已知問題清單，有安全解法就套用、只重跑失敗那一步，沒有就講清楚原因問你 retry 還是 stop。 Roughly 15–25 minutes overall (not counting how long you let each demo run, or flashing and its two manual switches); if any step fails, the script halts immediately — the agent checks a documented troubleshooting reference and applies a known-safe fix (re-running only that step) if one matches, otherwise explains the cause and asks whether to retry or stop.

為什麼要用 WSL？Why WSL?

  • iQ-Foundry 的工具鏈原生依賴 Linux 環境，沒辦法直接在 Windows 上跑；WSL2 能在 Windows 裡跑一份真正的 Ubuntu，不用另外雙系統或找一台 Linux 機器。 iQ-Foundry's toolchain natively depends on a Linux environment and can't run directly on Windows. WSL2 runs a real Ubuntu inside Windows, so there's no need to dual-boot or find a separate Linux machine.
  • Ubuntu 啟動後，Windows 會透過 usbipd 把接在主機上的 Q911 USB 裝置轉發進 WSL2，讓 Ubuntu 裡的工具可以直接操作它。 Once Ubuntu is up, Windows uses usbipd to forward the Q911 USB device plugged into the host into WSL2, so the tools inside Ubuntu can operate it directly.

Ubuntu 跑在 Windows 裡的 WSL2 環境中；Q911 實際接在 Windows 上，透過 usbipd 轉發進 WSL2 給 Ubuntu 用。 Ubuntu runs inside Windows via the WSL2 environment; Q911 is physically plugged into Windows, and usbipd forwards it up into WSL2 for Ubuntu to use.

為什麼要登入 Qualcomm AI Hub？Why log in to Qualcomm AI Hub?

  • iQ-Foundry 目前整合 Qualcomm AI Hub API，把模型推送到雲端進行轉換。 iQ-Foundry currently integrates the Qualcomm AI Hub API to push models to the cloud for conversion.
  • 需要先用 token 登入，才能呼叫這個 API。 You need to log in with a token before this API can be called.
  • 目前已經量化好的模型也放在 package 中了 —— 不想處理 API key 的話，可以直接改用離線模式。 An already-quantized model is also included in the package — if you'd rather not deal with an API key, just use offline mode instead.

量化在做什麼？What does quantization do?

  • NPU 對整數運算比較友善，模型進行量化才可以使用整數進行運行。 The NPU handles integer math far better — the model has to be quantized before it can run on integers.
  • 從 INT8 tflite 2.6 MB／FP32 tflite 9.4 MB，就會發現 int8 模型相對小很多。 INT8 tflite is 2.6 MB vs. FP32 tflite's 9.4 MB — the INT8 model is much smaller.
  • 量化模型做了什麼？ What does quantizing actually do?

透過 calibration data 決定 FP32 映射到 int8 的位置。 Calibration data decides where each FP32 value maps to in INT8.

  • package 中已放 50 張 calibration images。 The package already includes 50 calibration images.
  • 這場工作坊直接用套件裡已經量化好的模型，跳過這個等待——若自己手動用 iQ-Foundry qc flow 量化，會將模型上傳 Qualcomm AI Hub 等回傳，大約需要 5–9 分鐘。 This workshop uses the pre-quantized model already in the package and skips this wait — quantizing it yourself via the iQ-Foundry qc flow uploads the model to Qualcomm AI Hub and waits for it to come back, roughly 5–9 minutes.

mAP 怎麼算的？How is mAP calculated?

  • mAP 測試最基礎上會選擇 80/20 法則，80% 的 training dataset，20% testing dataset 用於測試 mAP。 By default, mAP testing follows the 80/20 rule — 80% training dataset, 20% testing dataset used to evaluate mAP.
  • 同一組圖片使用 trained model FP32 和量化 model INT8 各跑一次，與 ground truth 比較。 The same set of images is run once through the FP32 trained model and once through the quantized INT8 model, then compared against ground truth.

  • 同一台板子、同一組影片、同一個 app，只是把模型從 FP32 換成 INT8 —— 這樣才能公平比較兩者的差異。 Same board, same set of videos, same app — only the model changes from FP32 to INT8, so the comparison stays fair.

為什麼接上相機那路比較慢？Why is the connected camera's channel slower?

接上手邊的 camera、real-time 辨識後，會發現這路比其他 channel 都來得慢。原因： Once you connect your own camera for real-time inference, you'll notice this channel runs slower than the other channels. Why:

MJPEG 你的相機 · 軟體解碼your camera · software decode
H.264 其他 8 路 · 硬體解碼（h264dec）the other 8 channels · hardware decode (h264dec)
  • Camera 使用 MJPEG，因此會使用軟體解碼。 The camera uses MJPEG, so it has to be decoded in software.
  • 硬體本身支援 h264dec，其他 channel 播的影片本身就是 h264 格式，所以沒有這個問題。 The hardware supports h264dec, and the other channels play back video that's already in h264 format, so they don't hit this problem.
  • 相機會自動調整曝光時間，也會讓畫面偶爾卡一下。 The camera also auto-adjusts its exposure time, which can add occasional stutter too.
